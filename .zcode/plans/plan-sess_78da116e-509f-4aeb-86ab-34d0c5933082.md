# Migrate Kodi auth from Zitadel to self-hosted Logto

## Why this is a small migration
- Backend consumes only `identity.subject` (+ `identity.email` in the invite-claim path) — both standard OIDC claims, no Zitadel-specific claims or Management API usage anywhere.
- Frontend uses `oidc-client-ts` code flow + PKCE, which works unchanged against any standard OIDC provider. Only config values, one registration hint, and naming change.
- Hard cutover (your choice): no password/subject mapping. Old Zitadel-subject rows orphan; users re-register. Same model as the Zitadel cutover.

## Inputs needed from you at implementation time
1. Logto endpoint base URL (e.g. `https://logto.spidmax.win`).
2. After console setup: the SPA **App ID** (Logto uses string IDs, not numeric).
3. Output of `curl <endpoint>/oidc/.well-known/openid-configuration` — I need the byte-exact `issuer` (Logto appends `/oidc`, e.g. `https://logto.spidmax.win/oidc`) and `jwks_uri`. Issuer mismatch by even a trailing slash breaks Convex verification.

## Logto console setup (new `docs/logto-runbook.md`)
- Create Application of type **Single Page App** (public, PKCE, no secret).
- Redirect URIs: `https://kodi.spidmax.win/auth/callback` **and** `https://kodi.spidmax.win/auth/silent-renew` (silent-renew iframe hits `redirect_uri`, so both must be registered — same as Zitadel).
- Post sign-out redirect URI: `https://kodi.spidmax.win/`.
- Enable **email** sign-up/sign-in with verification-code connector (the invite-claim flow trusts the token email; usernames-without-email would break tenant claiming).
- Leave public registration open (your choice). Scopes granted: `openid profile email offline_access`.

## Changes

**Backend (1 file, then `npx convex deploy` — auth config only takes effect after deploy):**
- `convex/auth.config.ts`: `issuer` → Logto issuer *with* `/oidc`; `jwks` → discovery `jwks_uri` (standard path, not Zitadel's `/oauth/v2/keys`); `algorithm` stays `RS256`; `applicationID` → Logto App ID (Logto ID-token `aud` = client ID, and the frontend keeps sending the ID token — same pattern as today). Refresh header comments. Also fix the stale `convex/schema.ts:40` "Convex Auth subject" comment → "OIDC subject".
- No schema, query, or invite-flow code changes.

**Frontend (rename `lib/zitadel.ts` → `lib/logto.ts`, minimal diff):**
- Env vars renamed: `VITE_LOGTO_ISSUER` (full issuer incl. `/oidc`, used as OIDC `authority`) + `VITE_LOGTO_APP_ID`. Identifier `zitadelConfigured` → `logtoConfigured`. All imports updated (`main.tsx`, `auth.tsx`).
- One behavioral change: `signUpRedirect` extra param `prompt: "create"` (Zitadel extension) → `first_screen: "register"` (Logto's register hint).
- Unchanged: code flow, `openid profile email` scopes, `localStorage` session store, `loadUserInfo`, iframe silent renew, returnTo sanitize logic, `/auth/callback` + `/auth/silent-renew` interception, `signoutRedirect` (Logto exposes `end_session_endpoint`), callback guards.
- Recommended one-word addition: `offline_access` scope so Logto issues rotating refresh tokens (`oidc-client-ts` consumes them transparently, making renew robust instead of iframe-only). Verify the grant is enabled in console.
- Copy updates: `AuthPages.tsx` ("hosted sign-in" wording), `InvitePage.tsx` ("registers via Logto"), `auth.tsx`/`main.tsx` comments.

**Env / build plumbing:**
- `apps/web/.env.example`, local `apps/web/.env` (you fill in), `Dockerfile` ARG/ENV names, `docker-compose.yml` required-arg names, README Dokploy build-arg list (also fixing its existing staleness — it omits the current Zitadel args).

**Docs:**
- New `docs/logto-runbook.md` (console setup, redirect URIs, verify curls, handoff block, email-connector requirement); delete `docs/zitadel-runbook.md`; README provider-name + `auth.config.ts` description updates.

## Verification gates
1. `npm run typecheck`, `npm run build`, `npm run test` (35/35).
2. Local round-trip: login → onboarding → logout → re-login; decode the ID token and confirm `aud` == App ID and `email` claim present (gate for the invite-claim flow — if `email` is absent from the Logto ID token, fix console scopes before proceeding; no code fallback planned since Logto includes email claims per granted scope).
3. Tenant invite-claim end-to-end (exercises the `email` match).
4. `npx convex deploy`, Dokploy web rebuild with the new `VITE_LOGTO_*` build args (Vite bakes at build time), live smoke test.
5. Rollback = revert commit; old Zitadel sessions can't collide (oidc-client-ts storage keys are namespaced by authority+client-id). Zitadel decommission is out of scope but unblocked after cutover.

## Explicitly out of scope
Account preservation/subject mapping, `@logto/react` adoption, changing callback URL paths, touching M-Pesa/HTTP/cron code, `vercel.json`/`netlify.toml` disposition.
